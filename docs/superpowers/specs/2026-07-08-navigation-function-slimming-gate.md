# 导航与功能入口瘦身 Gate

## 结论

下一步先做导航和功能入口瘦身，不动经营总览首屏，不新增业务能力。

一级导航收敛为：

1. `经营总览`
2. `排班`
3. `待办`
4. `系统管理`

这次瘦身的目标不是删除现有功能，而是把功能重新归位：主业务放在业务入口，流程处理放进待办，数据和配置能力沉到系统管理。

## 本次做什么

- 取消当前侧边栏分组表达，不再展示 `运营工作台 / 计划与排班 / 日志数据 / 主数据` 这类分组标题。
- 把 `需求计划 / 排班计划 / 月班表草稿 / 正式班表 / 履约风险` 收到 `排班` 模块。
- 把 `班务申请中心 / 班务变更申请 / 复核案例 / 风险处理 / 数据确认 / 发布确认` 归入 `待办` 模块的处理心智。
- 把 `主数据 / 数据导入 / 业务版本 / 字段映射 / 状态日志 / 系统设置` 收到 `系统管理`。
- 保留现有路由作为兼容入口，第一轮只改产品入口、导航命名和入口归属。
- 明确旧命名废弃：`班务申请中心`、`班务变更申请`、`班表变更中心`、`变更治理`、`处理台`、`数据后台`。

## 本次不做什么

- 不改 `/dashboard` 第一屏布局、指标、图表或默认内容。
- 不删除现有页面文件、API、数据库表、迁移或测试。
- 不新增审批、权限、通知、催办、撤回、评论、导出、批量、外部集成、预测模型、标准人力、Excel 导入、自动排班、生产公式、结算或计费规则。
- 不把 `待办` 做成流程引擎、审批中心或抽象工作流平台。
- 不把技术概念暴露给业务用户，例如版本差异、source cell、revision、change governance。

## 模块定义

### 经营总览

定位：管理者入口，看经营状态和供需/履约概览。

本次不改首屏，只保留为首页入口。

### 排班

定位：所有排班相关的计划、班表、风险和明细查看。

模块内建议承载：

- `需求预测`：原 `需求计划`，表示预测需要多少人。
- `供需计划`：原 `排班计划`，表示计划排了多少、还缺多少。
- `月班表`：承载草稿和正式班表。
- `履约风险`：作为排班风险下钻，不再单独作为一级入口。
- `班次明细`、`不可用记录`：作为排班计划、履约风险或月班表的下钻视图。

### 待办

定位：统一处理所有需要人介入的事项。

模块内建议承载：

- `班务申请`：请假、换班、补班、现场调整等。
- `复核案例`：导入、对比、异常带来的数据复核。
- `风险处理`：履约风险确认和关闭。
- `数据确认`：导入准备度、业务版本确认。
- `发布确认`：月班表发布前后的确认事项。

`待办` 是统一入口，不替代业务详情。点击待办后仍回到对应业务详情处理。

### 系统管理

定位：低频管理、配置和数据维护。

模块内建议承载：

- `主数据`
- `数据导入`
- `业务版本`
- `字段映射`
- `状态日志`
- `系统设置`

`系统管理` 放侧边栏底部，不和业务入口抢优先级。

## 第一轮实施边界

允许改：

- `components/app-sidebar.tsx`
- 必要的导航结构测试
- 必要的页面标题、入口文案和兼容跳转
- 当前层和追踪文档

第一轮不允许改：

- `app/dashboard/page.tsx`
- 后端 API、服务、数据库、迁移
- package 或 lockfile
- 业务计算口径、状态码、公式、结算或计费规则
- 真实集成、权限、审批、导出、批量能力

## 验收标准

- 侧边栏只暴露 `经营总览 / 排班 / 待办` 三个业务入口，`系统管理` 在底部。
- 侧边栏不再展示旧分组标题。
- 侧边栏不再平铺 `需求计划 / 排班计划 / 月班表草稿 / 正式班表 / 班务申请中心 / 班务变更申请 / 履约风险 / 日志数据 / 主数据`。
- 现有路由仍可访问，不因导航瘦身被删除。
- `/dashboard` 首屏没有被改动。
- 页面和导航不出现 `班表变更中心`、`变更治理`、`处理台`、`数据后台` 作为业务入口。
- `bash scripts/check-state.sh --strict`、`git diff --check`、`bash scripts/check.sh` 通过。

## 后续实施建议

下一步创建一个 `frontend-scaffold` 小任务，只做导航入口瘦身和命名收口。若实施中发现需要新增权限、用户角色识别、流程引擎、后端聚合待办 API 或路由重构，必须停止并重新开 Gate。
