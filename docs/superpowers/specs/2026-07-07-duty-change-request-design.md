# 班务变更申请产品原型 v1.0

## 结论

`班务变更申请` 是排班师处理班长和一线提交的请假、换班、异常修复、现场调配申请的工作入口。页面主对象是一条申请，不是发布后变更事件、版本链或技术差异。

## 本轮做什么

- 将 `/roster-change-governance?month=2026-08` 的业务表达切到 `班务变更申请`。
- 第一屏呈现 `待处理 / 跟进中 / 已处理 / 按员工`。
- 点击申请打开右侧详情抽屉。
- 待处理详情提供 `同意 / 拒绝 / 现场跟进`。
- 同意后进入 `跟进中`，下一步是 `去调整班表`。
- 月班表调整承接申请上下文：顶部固定条、员工日期定位、`保存调整`。
- 保存调整后回到 `班务变更申请 > 已处理`，展示处理结果和班表结果。

## 本轮不做什么

- 不做审批、权限、通知、导出、批量处理。
- 不做自动改班、自动推荐、自动排班。
- 不做真实外部系统集成。
- 不把版本、差异、`source_cell_id`、revision 作为页面主对象。
- 不继续使用 `确认这条变更` 作为主动作。

## 页面 2：月班表调整承接

同意后打开月班表调整，顶部固定当前申请：

```txt
当前处理申请
张三 / 8月12日 / 请假
当前班次：A5 09:00-14:30
申请内容：改为休息

[返回申请] [标记现场跟进]
```

班表自动定位员工和日期：

```txt
员工      8/10     8/11     8/12              8/13
张三      A5       A5       A5 09:00-14:30    休息
                            当前申请
```

右侧调整：

```txt
来自申请
请假：申请改为休息

当前班次
A5 09:00-14:30

调整为
[休息 v]

备注
[病假，已同意申请]

[保存调整]
```

保存后回到已处理详情：

```txt
处理结果
已完成班表调整

班表结果
A5 09:00-14:30 -> 休息

[处理下一条]
```

## 状态规则

```txt
待处理
  - 同意 -> 跟进中 / 去调整班表
  - 拒绝 -> 已处理 / 班表未变更
  - 现场跟进 -> 跟进中 / 等待现场确认

跟进中
  - 去调整班表 -> 保存调整 -> 已处理
  - 现场确认后同意 -> 去调整班表
  - 现场确认后拒绝 -> 已处理

已处理
  - 已完成班表调整
  - 已拒绝
  - 现场确认后关闭
```

## 旧方向处置

废弃 UX 执行方向：

- `班表变更中心`
- 发布后变更事件作为主对象
- `确认这条变更`
- 版本时间线
- 差异审计页
- `source_cell_id`、revision、工程差异作为业务页面默认表达

保留资产：

- 现有路由 `/roster-change-governance` 可作为兼容入口。
- 已有正式班表、月班表调整、下游申请数据链路可作为后续实现素材。
- 已有测试和 Harness 规则保留。
