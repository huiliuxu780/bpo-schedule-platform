# Database Gate Plan

## Gate Decision

PM confirmed on 2026-05-28 that the project may enter database Gate planning.

DB001 is documentation-only. It does not authorize database implementation. It only defines the persistence boundary, task order, verification expectations, and stop conditions for later PM-confirmed implementation tasks.

## Allowed In DB001

- Define database Gate scope.
- Define entity sequence and dependency order.
- Define future implementation tasks.
- Define verification expectations.
- Update Harness state, requirements, stories, backlog, audit, and branch logs.

## Forbidden In DB001

- Database connection code.
- ORM models.
- Repository or adapter code.
- Migration files.
- Schema files.
- Production persistence config.
- Package or lockfile changes.
- Real CORN, HR, WFM, Excel, or third-party integration.
- Auth, permissions, supplier isolation, approval, export, batch operations, automatic scheduling, production formulas, settlement rules, or charge factors.

## Persistence Scope Order

The first database stage should follow this order:

1. Import batch foundation.
2. Import raw rows and failed rows.
3. Version records generated by imports.
4. Master data entities and bindings.
5. Personnel schedule details and half-hour expansion.
6. Demand forecast versions and rows.
7. Login and status logs.
8. Schedule-vs-actual comparison results.
9. Data quality issues.
10. Supervisor review conclusions, evidence, and closure records.

## First Implementation Slice

DB002 should persist import batch foundation only:

- Import batches.
- Import row results.
- Failed row details.
- Import-generated version records.

This slice is first because every later production entity needs a durable import source, row-level error trace, and version reference.

## Deferred Production Capabilities

These remain out of scope until separate PM confirmation:

- Authentication.
- Role and supplier permission isolation.
- Approval and publish workflow.
- Export.
- Batch operations.
- Automatic scheduling.
- Production status-code finalization.
- Capacity formulas.
- Settlement rules.
- Charge factors.
- Real external system integration.

## Future Task Map

| Task | Purpose | Implementation Boundary |
| --- | --- | --- |
| DB002 | Import persistence foundation | DB connection, migration strategy, import batches, row results, failed rows, versions |
| DB003 | Master data persistence | employees, suppliers, workplaces, projects, skills, bindings, validity and freeze status |
| DB004 | Personnel schedule persistence | schedule versions, schedule details, shift references, half-hour expansion |
| DB005 | Forecast persistence | forecast versions and interval rows |
| DB006 | Actual log persistence | login events, status intervals, business-day and timezone normalization |
| DB007 | Comparison persistence | forecast-vs-schedule and schedule-vs-actual result storage |
| DB008 | Review closure persistence | review conclusions, evidence, closure records, source references |
| Q127 | Database foundation QA | migration/test/check evidence and no-scope-leak audit |

## Required Confirmation Before DB002

DB002 must not start until PM confirms:

- Database engine.
- Local database runtime.
- Dependency and package-change allowance.
- Migration tool.
- Test database setup.
- Whether the first slice may modify backend code.
- Whether existing process-memory APIs should dual-write or switch behind repositories.
