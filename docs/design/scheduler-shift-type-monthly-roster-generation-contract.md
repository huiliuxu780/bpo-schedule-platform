# 班种定义与月班表生成底座产品契约 v0.1

## 1. 文档定位

本文定义第一版排班师月班表生成底座：班种定义、人员级日班种草稿、复制生成规则、版本状态和派生校验边界。

本文不授权前端或后端实现，不授权数据库 schema/migration，不授权 Excel 上传解析，不授权真实预测源接入，不授权标准人力模型，不授权自动排班，不授权审批、权限、通知、导出、批量、生产公式、结算或收费因子。

## 2. 已确认产品决策

| 决策项 | 第一版口径 |
| --- | --- |
| 生成目标 | 系统生成 `员工 + 日期 + 班种/标注` 的人员级日班种草稿 |
| 派生视图 | 每天班种人数、半小时覆盖、Forecast vs Arranged/Actual 人头差异均从人员级日班种派生 |
| 班种计算 | 只用工作时段展开半小时覆盖；用餐/休息、哺乳假、特殊激励、仅适用人头先记录不计算 |
| 复制生成 | 复制上一月或上一周的稳定班种规律 |
| 标注继承 | 不继承一次性请假、培训、会议、支援、离职等标注，转为待排或异常提示 |
| 待排人员 | 新人、转组、来源缺失人员只进入待排队列，不推荐班种 |
| 状态流转 | `draft` 草稿 -> `published` 发布版本；第一版不做审批 |
| Primary/Actual | `Primary Duty` 是计划班表；`Actual Duty` 是实际班表或调整后履约版本 |

## 3. 角色边界

| 角色 | 第一版纳入 | 后续延展 |
| --- | --- | --- |
| 排班师 | 生成草稿、调整人员日班种、处理待排和异常、发布计划班表 | 更复杂的推荐、批量、规则配置 |
| 小组长 | 后续读取发布版本和实际调整结果 | 调配、请假换班、数据修正的发起或审批 |
| 一线员工 | 后续读取个人已发布班表和实际状态 | 异常修复申请、请假、换班、调班 |

第一版底座必须为后续小组长和一线员工场景保留数据结构，但不得把审批、申请、权限或通知混入本期。

## 4. 核心对象契约

### 4.1 ShiftType

班种定义是生成和覆盖展开的基础字典。

| 字段 | 说明 | 第一版计算 |
| --- | --- | --- |
| `shift_code` | 班种代码，例如 `F3`、`T1`、`Z1`、`C4'` | 主键级业务代码 |
| `display_name` | 班种展示名或分类 | 展示 |
| `work_segments` | 一个或多个工作时段，例如 `07:00-15:00`、`06:30-11:30&22:00-24:00` | 用于半小时覆盖 |
| `crosses_day` | 是否跨自然日，例如 `22:00-07:00` | 用于展开到次日 |
| `work_hours` | Excel 班时 | 记录与校验提示 |
| `meal_or_break_note` | 用餐或休息描述 | 记录，不扣减 |
| `special_rule_note` | 哺乳假、特殊激励、仅适用人头等说明 | 记录，不计算 |
| `active` | 是否可用于生成 | 生成时过滤无效班种 |

班种时间解析规则：

1. 支持单段班：`07:00-15:00`。
2. 支持两段班：`06:30-11:30&22:00-24:00`。
3. 支持跨天班：结束时间早于开始时间时，结束落到次日。
4. 第一版半小时覆盖按工作时段占用展开，不扣用餐、休息、哺乳假。
5. 无法解析的班种不得静默生成覆盖，必须进入异常清单。

### 4.2 RosterAssignment

人员级日班种是第一版月班表源数据。

| 字段 | 说明 |
| --- | --- |
| `roster_version_id` | 月班表版本 |
| `business_date` | 业务日期 |
| `employee_id` | 系统员工 ID |
| `employee_external_id` | SAP 或外部员工号 |
| `project_id` / `team_id` | 项目和小组 |
| `workplace_code` | 职场或区域 |
| `assignment_kind` | `shift`、`annotation`、`rest`、`unassigned` |
| `shift_code` | 稳定班种代码 |
| `annotation_code` | 请假、培训、会议、支援、离职等标注代码 |
| `source_pattern` | `copied_previous_month`、`copied_previous_week`、`manual_edit`、`excel_initial_import` |

生成草稿时，系统的主输出是 `assignment_kind=shift` 的稳定班种记录；一次性标注不复制为正式日班种。

### 4.3 RosterVersion

| 字段 | 说明 |
| --- | --- |
| `business_month` | 目标月份 |
| `version_type` | `primary` 或 `actual` |
| `status` | `draft` 或 `published` |
| `source_type` | `copied_previous_month`、`copied_previous_week`、`excel_initial_import`、`manual_edit` |
| `source_reference` | 来源月份、来源周或初始化文件 |
| `created_by_role` | 第一版为 `scheduler` |

第一版只允许排班师把计划班表从草稿发布为正式版本。发布后版本作为小组长和一线员工后续查看的稳定来源。

### 4.4 PendingRosterEmployee

| 字段 | 说明 |
| --- | --- |
| `employee_id` | 待排员工 |
| `business_month` | 目标月份 |
| `reason` | `new_employee`、`team_changed`、`missing_source_pattern`、`invalid_shift_type`、`invalid_employee_status` |
| `team_id` / `project_id` | 当前归属 |
| `source_reference` | 来源月份、来源周或导入记录 |

第一版只提供待排原因，不提供推荐班种。

## 5. 月班表生成流程

### 5.1 输入

1. 目标月份。
2. 当前有效员工、项目、小组、职场归属。
3. 有效班种定义。
4. 复制来源：上一月计划班表，或上一周已确认规律。
5. 可选的 Forecast agents 外部输入或初始化缓存，只用于差异校验，不参与预测建模。

### 5.2 生成规则

1. 系统读取来源版本中的人员级日班种。
2. 只复制当前仍有效、且仍在同一项目和小组的员工。
3. 只复制稳定班种，不复制一次性标注。
4. 新员工、转组员工、来源缺失员工进入待排队列。
5. 来源班种不存在、停用或无法解析时，该员工日期进入异常清单。
6. 系统生成 `draft` 计划班表。
7. 排班师在草稿中人工补待排人员、修正异常、调整班种。
8. 排班师发布后形成 `published` 计划班表。

### 5.3 派生结果

| 派生结果 | 来源 | 用途 |
| --- | --- | --- |
| `ShiftDailyCount` | 人员级日班种按日期和班种汇总 | 查看每天各班种人数 |
| `RosterCoverageInterval` | 日班种 + 班种工作时段展开 | 查看半小时已排人头 |
| `RosterGapInterval` | Forecast agents 与已排/实际人头对比 | 发现人头缺口或冗余 |

派生结果不得反向成为源数据。排班师调整的对象仍然是人员级日班种。

## 6. Primary 与 Actual 关系

| 类型 | 定位 | 第一版处理 |
| --- | --- | --- |
| `Primary` | 计划班表 | 系统生成草稿并发布 |
| `Actual` | 实际班表或调整后履约版本 | 作为后续请假、换班、异常修正后的结果层 |

第一版生成底座必须区分计划和实际，但本期产品契约不实现实际调整流程。后续小组长调配和一线员工申请应写入 Actual 或调整记录，而不是覆盖 Primary 的来源语义。

## 7. 异常与提示

| 场景 | 第一版处理 |
| --- | --- |
| 新员工 | 进入待排队列 |
| 转组或项目变化 | 不复制原来源班种，进入待排队列 |
| 离职、无效员工 | 不复制 |
| 班种不存在或停用 | 进入异常清单 |
| 班种时间无法解析 | 不生成覆盖，进入异常清单 |
| 一次性标注 | 不复制为新月班表；作为提示呈现给排班师 |
| Forecast agents 缺失 | 允许生成草稿，但差异校验显示缺少预测输入 |

## 8. 验收口径

第一版产品契约通过标准：

1. 明确系统生成的是人员级日班种草稿，而不是只生成班种人数或半小时覆盖表。
2. 明确班种定义第一版只用工作时段参与半小时覆盖展开。
3. 明确复制上一月/上一周时不继承一次性标注。
4. 明确待排队列只给原因，不做推荐班种。
5. 明确状态流转为 `draft -> published`，不做审批。
6. 明确 `Primary Duty` 和 `Actual Duty` 的计划/实际分层。
7. 明确预测模型、标准人力、自动排班、审批、权限、通知、导出、批量、外部集成和生产规则均延后。

## 9. 推荐实现切片

1. 班种定义解析与半小时展开：单段、两段、跨天，异常清单。
2. 人员级月班表草稿对象：`RosterVersion`、`RosterAssignment`、待排队列的本地模型。
3. 复制上一月/上一周生成草稿：有效员工过滤、稳定班种继承、一次性标注剔除。
4. 发布版本与派生视图：`draft -> published`、班种人数、半小时覆盖、Forecast vs Arranged 差异。

暂不建议先做 Actual 调整、请假换班、小组长审批、一线员工申请、预测模型、标准人力和自动推荐。原因是这些都依赖人员级日班种和班种展开底座稳定。
